# CLAUDE.md

Guidance for Claude Code in this repository. Read `AGENTS.md` for the full layout, commands,
and the spec-to-enforcement workflow; this file is the short version of what matters most.

## Hard rules

- **Load the `rust` skill (`.claude/skills/rust/`) before writing or reviewing Rust.** It holds the
  house rules on lints, panics, errors, determinism and tests.
- **This repository is public.** Never commit an adopter's spec, schema, generated output or
  data, not even as a test fixture. Write fixtures from scratch; an adopter's spec stays in the
  adopter's own repository.
- **A spec value reaches SQL only as a quoted literal.** Every string from a spec goes through
  `demesne_runtime::quote_literal`, and a spec string that lands where SQL expects an identifier is
  refused unless it is a plain identifier. `crates/parity/tests/spec_strings.rs` appends a quote to
  every string in the corpus and checks none escapes its literal.
- **No comments in code.** Strip them. Only `// Code generated … DO NOT EDIT.` and functional
  directives survive. A comment belongs only when there is a firm, concrete reason; if it is a
  maybe, remove it and make the code clearer. Rustdoc on a published crate's public items is API
  documentation, not a comment: document them, with `# Errors` and `# Panics` where they apply.
- The compiler, CLI and runtime are the Rust workspace under `crates/`, and `@foir/demesne` and
  the Go module under `go/` run the Rust runtime as WebAssembly. The Go module is a thin layer:
  it never reimplements a runtime operation, and `go/runtime.wasm` is rebuilt with
  `scripts/build-go-wasm.sh`, never edited. The frozen Go engine (v0.93.x) lives on
  `release/v0.93` and its tags, and `scripts/parity` builds it from a tag to diff the Rust build
  against.
- **Unsafe code is forbidden in every crate but `runtime-abi`.** Its plain WebAssembly exports
  need `#[unsafe(no_mangle)]`, and handing a buffer back to the host needs one
  `Box::from_raw`. Each such item carries `#[expect(unsafe_code, reason = …)]` and each unsafe
  block a `SAFETY` comment; every other crate root has `#![forbid(unsafe_code)]`.
- The root `go.mod` exists only to retract v0.94.0 and v1.0.0 through v1.999.999, because each
  `vX.Y.Z` tag on `main` is also a version of the Go module `github.com/foir-io/demesne`. Without
  the range, `go get -u` would move Go users onto a version with no Go code. Keep it. The Go
  layer is the separate module `github.com/foir-io/demesne/go`, tagged `go/vX.Y.Z`.
- Keep every suite green. Regenerate the goldens with
  `UPDATE_ORACLE=1 cargo test -p demesne-parity --test goldens --test oracle_manifest`; never
  hand-edit a generated file.
- Every CLI output is pinned by snapshots in `crates/parity/tests/snapshots/`. After an intended
  output change, run `INSTA_UPDATE=always cargo test -p demesne-parity --test pinned_output`
  and read the whole diff before committing it.

## Fast commands

- Rust: `cargo test --workspace && cargo clippy --workspace --all-targets`
- Live Postgres suites: `DEMESNE_PG_URL=… SUPABASE_DB_URL=… cargo test -p demesne-postgres -- --ignored`
- Parity against the frozen Go engine: `demesne-parity run --go-tag <tag> --go-cli <go demesne> --rust-cli <rust demesne> --out <dir>`,
  `scripts/parity/live-db.sh`, `scripts/parity/dsn.sh`, and `node scripts/parity/wasm.mjs` after
  `scripts/build-wasm.sh`
- TypeScript: `scripts/build-runtime-wasm.sh`, then `cd ts && pnpm -r test`
- Go: `scripts/build-go-wasm.sh`, then `cd go && go test ./...` and `cd go/example && go test ./...`;
  `scripts/check-go-emit.sh` compiles the Go emitted for every corpus spec
- VS Code: `cd editors/vscode && npm run build:wasm && npm test`

## Cutting a release

Releases of the Rust workspace come from `main`: the crates, the CLI archives, the npm
packages `@foir/demesne`, `@foir/demesne-cli` and its five platform packages, and the Go module
`github.com/foir-io/demesne/go`.

1. Set the version in the root `Cargo.toml` (`[workspace.package]` and every
   `[workspace.dependencies]` entry) and promote the CHANGELOG's `## Unreleased` heading to
   `## vX.Y.Z`.
2. Merge to `main`.
3. Tag `vX.Y.Z` on `main` and push it. `.github/workflows/v-release.yml` builds the five
   archives and creates the GitHub release; its publish job, `publish-npm.yml`, stages each npm
   package for a maintainer to approve. npm's trusted publisher for every package names
   `v-release.yml`. The workflow is generated by dist from `dist-workspace.toml`: change the
   config and run `dist generate --mode ci`, never edit it. Tag `go/vX.Y.Z` on the same commit
   and push it too; that releases the Go module, and starts no workflow. A fix to the Go layer
   alone ships as a Go patch, `go/vX.Y.Z+1`, with the runtime unchanged.
4. Publish the crates from the tag, into an empty target directory:
   `CARGO_TARGET_DIR="$(mktemp -d)" cargo publish --workspace`. Cargo reuses a compiled
   registry crate of the same name and version, so a target directory that holds an earlier dry
   run's build verifies each crate against that stale build and fails.
5. Verify the release assets, `npx @foir/demesne-cli version`, each crate on crates.io, and the
   Go module: `GOPROXY=direct go list -m github.com/foir-io/demesne/go@vX.Y.Z`.

`tag-namespace = "v"` keeps the release run to tags that start with `v`, so the Go module's
`go/vX.Y.Z` tags and the Go engine's `pgx/vX.Y.Z` tags on `release/v0.93` start no run.

**Go library fixes (v0.93.x) go on `release/v0.93`**, cut from the last v0.93 tag when the
first fix is needed. A tag runs the workflow at its own
commit, so tags cut there still release through goreleaser. Go resolves a submodule only from
a path-prefixed tag, so tag **both** `vX.Y.Z` and `pgx/vX.Y.Z` there, bump
`cmd/demesne/go.mod` and `pgx/go.mod` to the new engine version (`go mod tidy` with
`GOWORK=off`), and check each module resolves:
`GOWORK=off GOPROXY=proxy.golang.org go list -m github.com/foir-io/demesne@vX.Y.Z` and the same
for `.../demesne/pgx@vX.Y.Z`. The proxy caches a negative result for a few minutes, so confirm
a new tag with `GOPROXY=direct` and wait the cache out.

**Order matters across repos:** release here first, then bump the adopter's pin. Pushing an
adopter PR that pins an unreleased version reddens its CI on work that is fine.

## Mental model

One `.demesne` spec compiles to two things: a Postgres RLS enforcement floor (the moat) and an
equivalence-checked, typed application surface (TypeScript, Go, and Rust through the crates). The
database decides; the generated check delegates to the same compiled predicate the RLS policy enforces. Do not
introduce a parallel evaluator, and do not let the application surface diverge from the floor.
